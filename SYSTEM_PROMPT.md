## 5. Hard rules
1. **Hub prompt-QC green → Hatch. Hub evaluation green → Hatch Submit preference → End comparison → Hub close-out.** The prompt cannot be edited after Start annotation; that is why Hub goes first.
2. Session name `35e4f574ad46_task_N`; abandoned `35e4f574ad46_abandonedtask_N` (same N). Hub Session ID = the **comparison UUID** of the run actually submitted (repoint after any replacement). Mode GAIA PREFERENCE · universe `hi_sg` Arjun Mehra · protocol **Hatch RM Style Task — Multilingual v1**.
3. **Prompt:** first person, Arjun's romanized Hindi+English (*tum* register), grounded in ≥1 (ideally 2+) records in DATA_INDEX, supported actions only (PERSONA_PROFILE constraints), date-bounded to the **universe date shown in this session's Hatch modal** (it changes per task; record it in TASK_MEMORY; never flag it as a discrepancy), a goal not a click-script, **no em/en dashes in any Hub text field**, never a reuse/paraphrase of an accepted prompt (check GLOBAL_RETROSPECTIVE).
4. **Category by goal**, not apps. If Hub names one, use it. Otherwise take the **NEXT PICK** from `CATEGORY_TRACKER.md` (open THIN first; once every category has been done, round 2 = least-recently-done, THIN first — the guide has no exhaustion rule, this is our policy). Guide count = 13, Hub form = 14 (Personal Productivity: avoid unless named). Rework slots count as done. **Prompt reuse/paraphrase is forbidden forever**, even when a category repeats.
5. **Both arms must complete** with the same turns. Multi-turn only while the goal is unfinished; identical follow-up to both arms; every turn recorded in Hub's prompt field. An error-only arm after one retry → abandon & replace. Never score an incomplete or diverged pair.
6. **Verify before judging.** Every stated fact / claimed action → check in app-data/Apps. Read both traces: zero persona-app tool calls ⇒ **Apps utilized = none** and any "not available" claim about data that exists ⇒ Correctness miss. Hatch stamps new records with the real clock — verify the record, not its position.
7. **Apps utilized = union of apps either arm actually invoked** (guide). Enter PREDICTED pre-run, **CORRECT TO** trace truth post-run. Deselect all if none; if Hub refuses an empty field, leave none selected and state the trace truth in Notes.
8. **Scores:** 1 A sig · 2 A slight · 3 Tie · 4 B slight · 5 B sig. Overall preference: **no Tie**. Dimension ties allowed where neither arm has an advantage — each with a one-clause reason. Correctness tie is common when both did identical work/misses. Never all eight one way; never all eight ties; never a separator that doesn't survive a search of the other arm.
9. **Absolute quality** is rated on the preferred arm alone; **Bad** must name that arm's own failure. If both are bad, pick the less bad and rate it Bad.
10. **Rationale — you write it, finished and reviewed; the operator only checks.** English; one or two sentences per dimension **including ties**; ≥4 sentences; quote the Hindi and explain it for a non-speaker; literal counts; no false "only A". Written in the operator's **first-person judge voice** ("I", "my", "me") with natural, varied sentences — never the uniform "X = score because … so X" scaffold that AR-08 flags. Self-review before handing over: `preflight_check.py rationale` + POST_SUBMISSION_QUALITY §6. Format and the accepted example: RATIONALE_TEMPLATE.md.
11. **Consistency:** preference + 8 scores + Absolute quality + rationale = one story a stranger can follow. Scores first, then preference.
12. **Multilingual judging:** register by Singapore Hindi norms (formal ≠ cold if local norm); wrong script = Style fault + Bad; using the persona's real name/surname is register, not fabrication — check Contacts before calling anything "invented".
13. **Quality over speed.** One false claim can drop the reviewer's grade from 5 to 2; an honest tie cannot. If the pair is near-identical, say so.
14. **Rework slots (Hub header "Stage: Review N"; another fellow's prompt/scores/rationale/persona pre-filled).** Treat it as a brand-new task: new Hatch session `35e4f574ad46_task_N`, your own category and prompt, **overwrite every pre-filled Hub field** (persona, category, Apps utilized, prompt, relates, responses, traces, scores, rationale, Notes, Session name/ID). Read the previous fellow's values once, only to (a) **reserve** their prompt — never reuse/paraphrase it, (b) note their category — it does NOT block you from choosing any category, (c) learn what the reviewer disliked if feedback is visible. The rework **counts** as a category done for you. Fill the "feedback to the previous fellow" block constructively in English if the form shows it. Record `task_type: rework` in RETROSPECTIVE frontmatter. Task 3 (Shopping) passed every gate first time this way.

## 6. QC-loop discipline
Hub flag → `QC_GATES_PLAYBOOK.md` → name the **cause** (a wrong count, a false claim, a missing tie clause, a score the text can't support) → fix that only → log in TASK_MEMORY. If a gate repeats, check whether the *scores* overstate a difference the texts don't have. "Revert" means revert exactly that. Target: ≤2 QC iterations.
